## Findings deferred (audited, real, not yet planned)

These came out of the same audit. They are listed here so the next run does not

FIFO, `-race` in CI and the shared-face question, lint on other targets,

Planned on 2026-11-14 as 016–020 and removed from this list: the render-path

- **The fallback cache is bounded by entry count, not bytes,** and long
  combining clusters are its keys (`context_puregoft.go:85-113`).
- **go-text allocates table buffers sized from untrusted header fields** (a few
  hundred bytes can ask for 4 GiB). The fix belongs in the typesetting fork, or
  in a pre-parse size check.
- **Unused WASM glyph cache** (found 2026-11-14). `Renderer.cache` and
  `pageKeys` in `renderer_wasm.go` are allocated but never written, because wasm
  draws with `fillText`. This is dead state kept for struct parity. Cleanup is
  optional.
- **Direction options** for the maintainer to weigh:
  - a supported glyph-visibility/reveal API (go-gui misuses
    `PangoGlyphUnknownFlag` for this)
  - per-line ink bounds (#160)
  - loading fonts from bytes without a temp file

## Findings considered and rejected

- "CI tests only on ubuntu": wrong. The `test-windows` and `test-macos` jobs run
  the full suite.
- Steady-state draw allocations: already 0 allocs/op (measured:
  `BenchmarkTerminalFrame1500`, `BenchmarkDrawLayoutPlacedCached`), with guard
  tests. No regression of #92/#151/#154.
- Removing the exported Pango/FreeType compatibility stubs needs a major
  version. The most that fits before then is a `// Deprecated:` note.
- `BlockStyle.Tabs` is accepted but does nothing. That calls for a doc note or a
  new feature, not a bug fix.
- Rich-text layout caching, the 15 allocs per shape inside go-text, and snapping
  mutation offsets to rune boundaries are low-confidence. Each needs
  investigation (profile, or check consumer usage) before any plan.
- `AddFontBytes` temp-file growth: low impact, and it falls under the "fonts
  from bytes" direction item.
- Layout-cache key collisions (`glyph.go:355`), re-vetted 2026-11-13: not
  practical. The variable-length strings are separated by fixed-width fields and
  a separator. A false hit needs a 64-bit FNV collision that someone crafts with
  embedded NUL bytes. With 8192 entries, an accidental collision has odds of
  about 2^-38.
- Fallback-cache byte bound: stays LOW. The cache is capped at 2^18 entries with
  cloned cluster keys (`context_puregoft.go:85`). Only adversarial huge
  combining clusters make it large.
- "WASM glyph cache never ages entries" (re-vetted 2026-11-14): there is no
  cache to age. WASM never writes `Renderer.cache` (`draw_wasm.go` draws with
  Canvas2D `fillText`). See the deferred "unused WASM glyph cache" item.
